## Construction pédagogique (sans nouveaux PowerPoint)

- [ ] Montrer le résultat attendu, réel ou explicitement simulé.
- [ ] Afficher et expliquer **le code tel qu'il était au module précédent**.
- [ ] Ajouter quelques lignes à la fois avec explication des variables, conditions et résultats.
- [ ] Exécuter ou montrer l'exécution attendue et préciser ce qui est effectivement vérifié.
- [ ] Faire reproduire une erreur sûre et sa correction.
- [ ] Faire modifier un paramètre ou une fonction à l'apprenant.
- [ ] Proposer les exercices, corrigés distincts et 10 QCM argumentés.

## Continuité technique (règle obligatoire)

- [ ] Le code principal évolue à partir de la version précédente : **pas de redémarrage de projet**.
- [ ] Les fonctionnalités précédentes sont conservées ou les migrations sont expliquées.
- [ ] Le mini-exercice et le code intégré sont tous deux disponibles.
- [ ] Si le firmware évolue : snapshot Mxx + dossier courant synchronisés.
- [ ] Si le firmware évolue : manifeste et matrice de progression actualisés.
- [ ] Si l'application Python/web évolue : même application et compatibilité des données/API préservées.
- [ ] Les tests couvrent la nouveauté et les acquis précédents.
- [ ] La compilation cible a été faite et ses résultats sont consignés (sinon écrire « non réalisée »).
- [ ] Le matériel réel est vérifié et la sécurité respectée (sinon écrire « non testé »).
